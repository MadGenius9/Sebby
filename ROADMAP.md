# Sebby roadmap and status

All seven phases are accepted development scope. A completed scaffold is not a completed phase. Credentials, costs, broader access, signing, publishing, and native Windows validation still require their own authority or environment.

1. **Foundation — implemented, native validation pending.** Electron shell, Orbit artwork, local memory/personality, honest draft/chat UI, scoped workspace reading.
2. **Real AI — blocked on secure credential decision.** Provider transport, streaming, cancellation, explicit context, history and budget/usage controls. Local conversation storage exists; no real provider calls. Voice exploration follows reliable text.
3. **Development workspace — partially implemented.** Reviewed hash-checked file edits, native consent, backup and undo; fixed command policy and fixture-tested cancellation/output bounds. Trusted Git status is wired. Windows npm execution remains disabled pending Job Objects. Real agent tool loop, preview/recovery workflow and Windows validation remain. **First useful app-developer milestone is the end of this phase.**
4. **Skills/connections — partially implemented.** Bundled/imported untrusted instruction registry and GitHub/MCP bookmarks. Actual scoped authentication/MCP tool transport and connection health not implemented.
5. **Specialist agents — identities and durable queue implemented, execution pending.** Sebby assigns names and clear jobs, persists team, supports rename/retire/task assignment; real queue status/logs and interrupted restart state. Future coordinator reviews evidence before completion. No extra permissions through delegation.
6. **Companion — partial.** Orbit art, stored personality, optional device-local speech preview, persistent in-app reminders. Rich voice, expressions, OS notifications, background/desktop/browser control and optional cloud not implemented.
7. **Release quality — partial.** Single-instance lock, bounded stores, backup/restore/journal recovery, security tests, component tests, NSIS configuration and manual Windows script. Native UI/E2E/Windows install, signing, trusted updates, accessibility review and crash/power-loss testing remain.

## Improvements included while building

- No fictitious model replies, agent progress, connector health, or usage metrics.
- Imported skill instructions cannot grant permissions or execute scripts.
- Hash-checked previews reject stale files and truncated review; undo also verifies current contents.
- Restarted work becomes interrupted rather than automatically replaying potentially destructive actions.
- Credentials excluded from backup schema; plaintext prompts and memory explicitly disclosed.
- Team identity, specialty, job and task evidence remain visible rather than hidden behind a generic spinner.

Future candidates: memory provenance, per-project budget/permission summaries, better text diff algorithms, and reversible batch changes. New costs, access, or privacy implications must remain explicit.

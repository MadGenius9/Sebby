# Sebby roadmap and status

All seven phases are accepted development scope. A completed scaffold is not a completed phase. Credentials, costs, broader access, signing, publishing, and native Windows validation still require their own authority or environment.

1. **Foundation — implemented, native validation pending.** Electron shell, Orbit artwork, local memory/personality, honest draft/chat UI, scoped workspace reading.
2. **Real AI — implemented in source, live validation pending.** Three typed provider transports, streaming/cancel, explicit context/history, model/output budget and reported usage. Existing-key reuse decision resolved; user configures a key securely at runtime. Mock transports tested; no real provider calls. Voice exploration follows reliable text.
3. **Development workspace — partially implemented.** Reviewed hash-checked file edits, native consent, backup and undo; fixed command policy and fixture-tested cancellation/output bounds. Trusted Git status is wired. Windows npm execution remains disabled. Job Object helper source exists, but has not been compiled, native-tested or integrated. Bounded approved read/edit agent tools are implemented; a sanitized static HTML/CSS preview is available in source. Interactive preview processes, safe build/test execution and Windows validation remain. **First useful app-developer milestone is the end of this phase.**
4. **Skills/connections — partially implemented.** Bundled/imported untrusted instruction registry and GitHub/MCP bookmarks. Read-only MCP tool-name discovery is implemented with fresh native consent and bounded pinned HTTPS (JSON-only modern subset; no real endpoint tested). Read-only GitHub token authentication and metadata/tree/verified blob source paths now exist, but live access is untested; remote mutations and MCP tool execution remain absent.
5. **Specialist agents — bounded execution implemented in source, live validation pending.** Sebby assigns names and clear jobs, persists team, supports rename/retire/task assignment; real queue status/logs and interrupted restart state. A separate provider coordinator reviews specialist evidence; user acceptance is still required before completion. Real deterministic local utilities can attach a specialist label and produce reviewed metadata evidence; these are not AI agents. No extra permissions through delegation.
6. **Companion — partial.** Nine original 3D pals with material color customization, stored personality, optional device-local speech preview, persistent in-app reminders plus opt-in session-only desktop notifications (native delivery unverified). Explicit microphone-to-draft transcription and local response reading are implemented and mock-tested. Native microphone/audio-provider validation, realtime conversational voice, expressions, background/desktop/browser control and optional cloud remain.
7. **Release quality — partial.** Single-instance lock, bounded stores, backup/restore/journal recovery, security tests, component tests, NSIS configuration, dependency-notice inventory/readiness gates and manual Windows script. Native UI/E2E/Windows install, signing, trusted updates, accessibility review and crash/power-loss testing remain.

## Improvements included while building

- No fictitious model replies, agent progress, connector health, or usage metrics.
- Imported skill instructions cannot grant permissions or execute scripts.
- Hash-checked previews reject stale files and truncated review; undo also verifies current contents.
- Restarted work becomes interrupted rather than automatically replaying potentially destructive actions.
- Credentials excluded from backup schema; plaintext prompts and memory explicitly disclosed.
- Team identity, specialty, job and task evidence remain visible rather than hidden behind a generic spinner.

Future candidates: memory provenance, per-project budget/permission summaries, better text diff algorithms, and reversible batch changes. New costs, access, or privacy implications must remain explicit.
